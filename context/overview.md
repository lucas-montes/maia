# Maia — Project Overview

## What is Maia?
A personal productivity suite with AI-powered features for managing todos, notes, expenses, calorie tracking, exercise, and knowledge base. Runs as a background daemon with CLI tools, Chrome extension, and file watchers.

## Architecture
- **Sync Server** (`sync-server` crate): Standalone Axum + rusqlite (bundled) + tokio HTTP server implementing the FitFat offline-first sync API. Deterministic `0.0.0.0:3030` LAN port, Bearer `Authorization` auth, `server_time` epoch ms, `since` cursors, `deleted[]` tombstones, WAL+FK, UUID v7 TEXT PK. Has its own binary (`serve`/`migrate`/`status`) and runs as the `maia` NixOS service. It is a separate process from the desktop app, which is a client of it. Configuration comes from a JSON file, never the environment. Schema is versioned by `PRAGMA user_version` (currently v3). See `context/plans/fitfat-sync-server.md` and `context/plans/maia-headless-server.md`.
- **Tauri Desktop** (`maia-ui/src-tauri`): Desktop shell with SQLite via rusqlite (single `maia.db`, `sync_server::db::migrate` only, no legacy `INTEGER AUTOINCREMENT` tables), UUID v7 (`Uuid::now_v7()`). A client of the sync server, not a host for it: it no longer spawns one, and reads the same config and database. Packaged as `maia-desktop` and installed by `services.maia.desktop.enable`.
- **Daemon** (root binary, deprecated): Background service with file watchers (inotify) and Unix socket listener — superseded by `sync-server` for FitFat sync; retained only for file-watcher legacy, not used by Tauri.
- **CLI tools**: Per-domain CLIs in `todo/`, `knowledge/` crates that communicate via socket (legacy)
- **Chrome extension + native messaging host**: Browser integration for bookmarks, reading list, context menus
- **Shared library**: Database models, CRUD macros, AI schema definitions
- **AI integration**: Gemini API for structured data extraction (receipts from images)

## Key Constraints
- Workspace: Rust edition 2024
- Database: SQLite via rusqlite
- Storage: Local-first (files + SQLite), remote storage planned
- Daemon uses Unix domain sockets for IPC (`/tmp/maia.sock`)

## Current State
- **Receipt OCR Pipeline** (`receipt-ocr-pipeline` plan) completed 2026-10-02: `POST /receipt-pictures/upload` (multipart, 202 + background `tokio::spawn` Gemini vision job) plus `GET /receipt-pictures/:id/parse` and `/:id/picture`; `ParsedReceipt` schema (`merchant`/`items`, matching the mobile draft builder) in `sync-server/src/receipt_ocr.rs`; `sync-server` gained an `ai` dependency and `Config.model_api_key: String`; `receipts` gained `parse_error`/`archived_path`/`archived_at` via guarded `ALTER TABLE`; upload body limit raised from axum's 2 MB default to 20 MB; `remote_path` now stored relative (was leaking absolute server paths to clients); desktop receipts view realigned to the v30 schema with working archive/restore (`<archived_dir>/<id>/{receipt.<ext>,receipt.json}`). 35 `sync-server` tests, 85 Flutter tests.
- **Headless Sync Server** (`maia-headless-server` plan) 2026-10-05: `sync-server` is now a binary as well as a library, so the API runs as the `maia` NixOS service on luctop instead of only while the desktop app is open. Schema moved from boot-time `CREATE TABLE IF NOT EXISTS` to an append-only `MIGRATIONS` list keyed on `PRAGMA user_version` (v1 schema, v2 `receipts` columns, v3 drop orphan `meal_ingredients`), each step in its own `BEGIN IMMEDIATE` transaction with a `VACUUM INTO` snapshot before every version change (keep 10) and a refusal to start when the database is newer than the binary. Configuration is file-driven: `/etc/maia/config.json` is generated by Nix and read by both the service and the desktop app, with a per-user `~/.config/maia/config.json` overlay for the desktop paths the Settings form owns. `POST /backup` is routed with a 256 MB limit and an atomic write. 41 tables in the v1 schema; the desktop app and the service share one `maia.db` and run as the same user, so owner permissions cover both.
- **Note:** `shared/src/purchases` (`schema.rs`, `models.rs`, `parse.rs`) is dead code — the module is private and `models::Receipt` maps to a `receipts` table shape that no longer exists. Superseded by `sync-server/src/receipt_ocr.rs`. Do not reuse it.
