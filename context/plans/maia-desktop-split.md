# Maia Desktop / Server Split

## Change summary
Stop the Tauri app from running a server, and move configuration from environment variables into a file generated by Nix.

`maia-ui/src-tauri/src/lib.rs` spawns `sync_server::server::start_server` in-process on the same port the systemd service already holds. That bind fails, only `eprintln!`s, and leaves `get_sync_port` returning `0` — so the phone-pairing QR renders `http://<ip>:0` and the diagnostics panel reports the wrong thing. Remove the embedded server and make the desktop app a pure client of the service.

Alongside that, replace the `MAIA_*` environment variables with a single Nix-rendered `/etc/maia/config.json`, and package the Tauri app as a real Nix derivation with a desktop entry so it can be launched on demand instead of through `pnpm tauri dev`.

Follows `maia-headless-server`, which built the service this one separates from the UI.

## Config shape
One file, rendered by `environment.etc`, containing everything including `api_key` and `model_api`.

Accepted trade-off: the key is then readable by any local user via `/nix/store`, which matches today's situation where it is hardcoded as `fitfat-sync-key` in the source. Keeping it out of the store was considered (sops, a separate root-only file) and rejected.

Deployment keys, from `/etc/maia/config.json`: `database`, `bind_addr`, `media_dir`, `seed_dir`, `notes_dir`, `api_key`, `model_api`, `model_name`.

Desktop keys, from `~/.config/maia/config.json`: `receipts_path`, `nutriments_path`, `bank_statements_path`, `investments_statements_path`, `receipts.archived_dir`.

The two key sets are disjoint, so merging is unambiguous. The deployment file wins for its keys, the overlay for its own.

## Success criteria
- [ ] Only one process ever listens on 3030; the app never binds it
- [ ] Pairing QR and diagnostics show the configured port, never `0`, with the service up *or* down
- [ ] `rg 'MAIA_'` → no matches; `Config::from_env` and `env_keys` deleted
- [ ] `/etc/maia/config.json` generated by Nix; firewall derives from the same `port` option, so no drift
- [ ] `get_server_logs` and the `state.fitfat.logs` plumbing gone from Rust and frontend
- [ ] `maia` in the app grid, opens `/var/lib/maia/maia.db`, video subtitles work
- [ ] Settings saves only `~/.config/maia/config.json`; `database`/`model_api` read-only
- [ ] `cargo test --workspace`, `pnpm build`, `nix build .#sync-server`, `nix build .#maia-desktop` green

## Constraints and non-goals
**Constraints:**
- No environment variables anywhere; the config file is the only configuration source
- The API key is not kept out of the store
- Desktop and service keep sharing one `maia.db` via the existing group/setgid/`UMask` arrangement

**Non-goals:**
- No TLS or key rotation
- No change to the HTTP API surface
- No mobile client work
- No hot reload; `cargo tauri dev` remains dev-only and now needs a separately running server

## Deviations from the plan

- **The GUI log panel did exist.** The plan recorded that `state.fitfat.logs` was
  populated but never rendered. That was wrong: a "Show Logs (N)" button and a
  "Recent requests" block rendered it, and an earlier grep missed both because the
  render path destructures `ff` rather than reading `state.fitfat.logs`. Both were
  removed along with the command.
- **`get_server_logs` was deleted rather than repointed** at `journalctl`, per the
  decision that the GUI should not surface service logs.
- **T04 needed no separate wrapper.** `wrapGAppsHook4` already turns `gst_*`
  buildInputs into `GST_PLUGIN_SYSTEM_PATH_1_0`, so the first attempt's
  `wrapProgram` only produced a `..maia-ui-wrapped-wrapped` nesting.
- **`desktopItems` does not exist** in this nixpkgs, so the desktop entry is
  written through `environment.etc` instead.
- **Two `git reset HEAD~` runs** moved `~/.dotfiles` master back past the commits
  made for the previous plan while leaving the work staged. The dotfiles state was
  rewritten as one commit rather than replayed.

## Remaining manual steps

1. `nix flake update maia` in `~/.dotfiles` after every commit in this repo — the
   input is locked, so a rebuild otherwise reuses the previous commit.
2. `sudo nixos-rebuild switch --flake ~/.dotfiles#luctop`.
3. Import the existing database so the phone's history is present:
   `sudo cp ~/Projects/maia/server/maia.db /var/lib/maia/maia.db`. It is gitignored,
   so copy it rather than expecting it in the store.
4. Put the `services.maia.apiKey` value in the phone's settings.
5. Confirm a video with a `.vtt` sidecar shows captions, which exercises the
   GStreamer plugin path on the installed binary.
